# Интерфейс и голос — план переработки (обсуждено 2026-09-12)

Источник: обсуждение «давай поговорим». Реализация — ПОСЛЕ отработки полного
сценария «пользователь на Windows скачивает и запускает программу».

## Решённые решения

### 1. Объединение всех режимов в один
- **TUI — единственный интерфейс**. Голос — не отдельный режим, а фоновый
  воркер внутри TUI: `--voice` умирает как концепция, остаётся `/voice on|off|tts|wake`.
- Голосовой воркер — tokio-задача: не трогает терминал (raw-mode у ratatui),
  кладёт услышанное в ту же очередь ходов, что и печатаемый ввод.
- `--simple` остаётся аварийным фолбэком; Telegram — отдельный транспорт.

### 2. Wake-word «Гефест» / "Hephaestus" (RU+EN)
- Реализация: **VAD (энергетический → потом silero) + Whisper tiny на
  кольцевом буфере ~10 сек + нечёткий матч** (Левенштейн, допуск 1–2 опечатки,
  словарь форм: «Гефест», «hefest», «Hephaestus»).
- CPU-трюк: Whisper крутится только когда VAD сказал «идёт речь».
- Ноль новых тяжёлых зависимостей (rwhisper уже в проекте).
- UX: вспышка «🎤 Гефест слушает…» + транскрипт; Esc прерывает как обычно.

### 3. Полная нативная поддержка Windows (не WSL!)
- Запись: **cpal → WASAPI** (кроссплатформенно, уже в зависимостях).
- STT: rwhisper (CPU ONNX) — работает на Windows.
- TTS Windows: **SAPI через PowerShell** (`System.Speech`, Irina/Dmitri из
  коробки; кириллицу подавать через UTF-8 файл параметров, не инлайн).
- Воспроизведение: **cpal output stream** на всех платформах — честный
  нативный звук из одного exe, без aplay/paplay.

### 4. Голосовые ответы на ВСЕХ платформах
Единый TTS-модуль с платформенным диспетчером:
| Платформа | Движок |
|---|---|
| Windows | SAPI (PowerShell, встроен в ОС) |
| Linux | espeak-ng (уже есть), опц. piper |
| macOS | `say` (встроен, Milena) |

### 5. Распознавание голосовых в Telegram
Telegram шлёт OGG/Opus. Конвейер pure Rust:
```
update(voice) → getFile → скачать OGG
  → symphonia (декодер Opus, pure Rust) → PCM
  → rubato (ресемпл 16кГц моно)
  → rwhisper (та же модель, что для wake-word) → текст
  → тот же chat(), что и текстовые
```

### 6. Ответ голосом В Telegram
Энкодера Opus в pure Rust зрелого нет. Решение — **грейсфул-фолбэк**:
- если в системе есть `opusenc`/`ffmpeg` → честная голосовая (sendVoice)
- нет → WAV через sendAudio (проигрывается в клиентах) или текст
- Никто не остаётся без звука; кросс-сборка Windows не ломается (вариант
  audiopus/static отклонён).

### 7. Архитектура после объединения
```
                 ┌── клавиатура (TUI, единственный интерфейс)
Agent::chat() ←──┤── микрофон-воркер: VAD → Whisper-tiny → wake «Гефест» → команда
                 └── Telegram: текст / голосовая (symphonia→Whisper) / cron
                        ↓
             ответ в чат + (опц.) TTS через cpal
             ТГ: текст + (опц.) голос через opusenc/ffmpeg → sendVoice
```
Одна Whisper-модель на всё: wake-word + ТГ-голосовые + TUI-диктовка.

## Открытые вопросы (спросить перед реализацией)
1. Wake word: команда в одной фразе («Гефест, запусти тесты») или активатор
   на 10 сек?
2. TTS-ответы по умолчанию: вкл или выкл (с быстрым включением)?
3. ТГ-ответы: текст+голос дублировать или только голос при включённом TTS?
4. opencode-косметика (тонкие панели/темы) — этой же волной или отдельно?

## Риски (зафиксировано честно)
- SAPI + кириллица (кодировка) — тестировать с UTF-8 файлом параметров.
- ТГ-STT на CPU: ~1–3 сек на голосовую — приемлемо.
- Микрофонный путь на нативной Windows не проверяем из этой среды — cpal/
  WASAPI зрелый, но живой прогон на реальной машине — первым делом.

   удалённый репозиторий, старый удалить. Выбор за пользователем после
   отработки сценария.
3. Вернуться к переработке интерфейса/голоса (этот план).
